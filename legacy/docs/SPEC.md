# SPEC: NYC "Are streets near newly completed affordable housing different, in crash patterns, from comparable streets?" (single source of truth)

## 1. Question
Are streets around newly completed affordable housing different, in police-reported crash patterns, from comparable streets, and does the pattern differ by borough, building size, construction type, and crash type? Audience: DOT/HPD planners, safety advocates.

## 2. Datasets (NYC Open Data, Socrata SODA API; columns below are VERIFIED real API field names)
- HOUSING `hg8x-zxpr` Affordable Housing Production by Building. 9,551 rows, 41 cols, ~7.6k with ZIP+lat/lon.
  project_id,project_name,project_start_date,project_completion_date,building_id,house_number,street_name,borough(Title case),postcode(number!),bbl,bin,community_board,council_district,census_tract,neighborhood_tabulation_area,latitude,longitude,latitude_internal,longitude_internal,building_completion_date,reporting_construction_type,extended_affordability_status,prevailing_wage_status,extremely_low_income_units,very_low_income_units,low_income_units,moderate_income_units,middle_income_units,other_income_units,studio_units,_1_br_units.._6_br_units,unknown_br_units,counted_rental_units,counted_homeownership_units,all_counted_units,total_units
  Unit columns are ABSENT from JSON when 0/null -> must exist after load (fill 0, justify).
- CRASHES `h9gi-nx95` Motor Vehicle Collisions - Crashes. 1,541,146 rows since 2016-01-01 (lat 92% non-null, zip 66%, borough 66%).
  crash_date,crash_time(text "H:MM"),borough(UPPER),zip_code(text),latitude,longitude,location,on_street_name,off_street_name,cross_street_name,number_of_{persons,pedestrians,cyclist,motorist}_{injured,killed},contributing_factor_vehicle_1..5,collision_id,vehicle_type_code1,vehicle_type_code2,vehicle_type_code_3..5
- Catalog lists T4 as "SIRTA Data"/crashes; H2 in catalog. Both in catalog -> no feasibility check needed (mention anyway).
- API: `https://data.cityofnewyork.us/resource/{id}.csv?$limit=..&$offset=..&$order=:id&$select=..&$where=..` (default limit 1000! always page). App token optional env `SOCRATA_APP_TOKEN`.
- Window: crashes 2016-01-01 .. last full calendar year (Y_END = config, default 2025). Housing completions 2014+ (needed for pre-windows) but panel years = 2016..Y_END.

## 3. Integration design (justify in notebook)
1. Administrative+temporal: ZIP x year panel (both have ZIP; year common). Chosen because ZIP present in both, ~190 NYC ZIPs x 10 yrs = adequate N, interpretable for planners. Crashes with missing ZIP are recovered (see 4) not dropped.
2. Spatial proximity: each crash flagged `near250` = within 250 m of ANY completed-by-then-or-ever housing building (haversine BallTree, radius 250/6371000 rad). Event study per building: crashes within 250 m in the 3 full years BEFORE vs AFTER completion year (completion year itself excluded), only buildings with full windows (comp_year-3>=2016 and comp_year+3<=Y_END). Normalise by city-wide crash index per year (city crashes in year / city mean over window) to remove COVID/citywide trend: adj_count = count / city_index[year].
3. No row-level join between datasets.

## 4. Cleaning rules (each logged to `cleaning_log` list of dicts: step,dataset,rule,rows_before,rows_after,rationale)
HOUSING: snake_case cols; ensure all unit cols exist, fill 0; parse dates; postcode->5-char str zero-padded, valid only if in NYC ZIP set (10001-10499,10500-11699 excluding non-NYC? -> use regex ^1(0[0-4]\d{2}|1[0-6]\d{2})$); borough canon {Manhattan,Bronx,Brooklyn,Queens,Staten Island}; coords must lie in NYC bbox lat[40.45,40.95] lon[-74.30,-73.65] else NaN; dup building_id keep last by completion date; completion<start -> flag `date_inconsistent`, set building_completion_date=NaN?? NO: keep building_completion_date, fall back to project_completion_date, year=comp_year; drop rows w/o any completion date from panel only (kept in housing_clean with flag `completed`=False); total_units<all_counted_units -> set total_units=all_counted_units; outliers: total_units IQR(1.5) flag `is_large_outlier` (kept,legit big projects; winsorise 99th pct only inside stats that need it, document); derived: comp_year, size_bin (quartiles of total_units), `income_low_share`=(extremely+very low)/all_counted, construction_type canon {New Construction,Preservation,Other}.
CRASHES: stream pages; parse date; year filter; hour from crash_time (invalid->NaN, hour_band: Night 0-5, Morning 6-11, Afternoon 12-17, Evening 18-23, Unknown); borough upper->Title canon; zip valid-regex else NaN; lat/lon bbox else NaN (0,0 junk); dup collision_id drop; injury/killed columns -> int>=0, if persons_injured < sum(ped,cyc,mot injured) set persons_injured=sum (consistency); outliers: persons_injured >20 -> flagged & capped at 20? use domain rule cap 20, log count; factor_group: map contributing_factor_vehicle_1 to {Distraction/Inattention, Speed/Aggressive, Failure to Yield/Signal, Impairment/Fatigue, Vehicle/Road Defect, Other, Unspecified}; severity {Fatal if killed>0, Injury if injured>0, Property damage only}; ped_cyc flag = ped or cyc injured/killed>0.
  ZIP recovery (post-integration-stage cleaning, required): grid-mode imputation: pass 1 builds dict cell(round(lat/0.002),round(lon/0.002)) -> modal ZIP from rows having both; rows missing ZIP but with coords get cell-modal ZIP (`zip_imputed`=True); borough from ZIP->modal borough map. Rows with neither ZIP nor coords: counted in `unlocated` (kept only in citywide totals, excluded from ZIP panel); report share. Validate imputation: hold out 5% of known-ZIP rows, report accuracy (log).
POST-INTEGRATION: panel left-joined from full universe ZIPxyear(2016..Y_END) of ZIPs seen in either dataset; housing-metric NaN -> 0 (structural zero: no completions), crash NaN -> 0 only if ZIP seen in crash data, else NaN-dropped; enforce dtypes (zip str, year int16, counts int32); drop redundant cols (latitude_internal, longitude_internal, bin, bbl kept only in housing_clean, community_board dup etc.); borough for housing-only ZIPs from mode; assert unique (zip,year); assert no negative; log counts of introduced NaNs and resolution.

## 7. Research questions (12; M1..M6 two each; team size N uses first 2N; README says how). Each = 1 chart. None simple counts; all non-causal wording.
RQ1 (M1) ZIP-level: units completed 2016-Y_END vs crash rate growth (crashes last3yrs / first3yrs), scatter log, Spearman, hover ZIP, size=units, color borough.
RQ2 (M1) Within-ZIP: does a ZIP's year-over-year crash change co-move with units completed that year? panel FE (demean by ZIP), scatter + OLS line, cluster-robust-ish (bootstrap by ZIP CI).
RQ3 (M2) Event study: adjusted crashes within 250 m, rel year -3..+3, line + bootstrap 95% CI, all eligible buildings.
RQ4 (M2) Dose-response: post-pre adjusted change by building size bin (bar + CI).
RQ5 (M3) New Construction vs Preservation event study difference (two lines).
RQ6 (M3) Ped/cyc: share of crashes with ped/cyc harm within 250 m vs elsewhere by borough (grouped bar + chi2/diff CI).
RQ7 (M4) Relationship map: housing buildings (bubble=units, color=comp year) over crash density grid for selected years (mapbox carto-positron, no token).
RQ8 (M4) Borough x year heatmap: units completed per 10k crashes? Use ratio units/crashes*1000 (document) as heat.
RQ9 (M5) Low-income share of ZIP completions vs injuries-per-crash severity (scatter, color borough, Spearman).
RQ10 (M5) Contributing-factor lift: P(factor|near250)/P(factor|not near) (horizontal bar, CI).
RQ11 (M6) Hour-band profile near vs not near (grouped bar/line, normalised shares).
RQ12 (M6) Lag cross-correlation per borough: units completed(t) vs crashes(t+lag), lag 0..3, heatmap of Spearman rho (n small; flag low N).
All stats report n, effect, CI or p; headline templates choose wording ("is associated with", "no clear difference") by CI sign; always append "association, not causation".

## 10. Failure-mode register (mitigations)
F1 API 403/timeouts/limit 1000 -> paging, retries, cache, app token. F2 memory blowup on 1.5M rows -> streaming chunks, select only needed cols, dtypes, aggregate incrementally. F3 schema drift CSV vs API names -> normalise names to lower snake, assert required cols, clear error. F4 missing JSON keys for null/zero -> reindex. F5 ZIP number->str with lost zeros. F6 spatial join wrongness -> haversine radians, verified vs brute force. F7 ecological fallacy/confounding/COVID -> city index normalisation, limits section, non-causal text. F8 tiny-N cells -> show n, suppress stats if n<8 ("insufficient data"). F9 callback/slow charts -> precomputed cubes. F10 Render 512MB -> build-time pipeline, slim parquet, categoricals. F11 survivorship: crash reporting practices changed (2016+ NYPD), late data lag in latest months -> Y_END full year only. F12 Fixture/real mix-up -> meta.fixture flag + banner.

A1 Paging: NOT `:id` (not sortable lexicographically, verified). A2 ZIP regex (excludes Nassau): `^(10[0-4]\d{2}|11[1-4]\d{2}|1100[45]|116\d{2})$`.
A3 `exposure` replaces `near250` in cube: int8 0=no housing building within 250 m ever; 1="pre": nearest building(s) complete AFTER crash year (every building within 250 m has comp_year > crash year); 2="post": some building within 250 m has comp_year <= crash year (2 wins). Buildings with no comp_year are ignored for exposure. RQ6/10/11 compare 2 vs 0, and show 1 vs 0 as placebo (dense-area baseline). Crash needs coordinates; crashes without coords get exposure=-1 → exclude from exposure analyses, keep in zip counts (cube field `exposure` int8, -1 allowed).
A4 Event study: unit = SITE. site_id = connected components of eligible+control buildings within 250 m sharing comp_year (union-find via BallTree query_radius pairs). `contaminated`=True if another completion (different site) lies within 250 m of any site building with |comp_year diff|<=3 (report results excluding contaminated as sensitivity). Treated cohort c: buildings with comp_year==c, c-3>=Y_START and c+3<=Y_END. Control: buildings with comp_year>=c+4 (incl. 2026), evaluated on the same calendar windows (rel_year = year-c). adj = crashes/city_index[year]; city_index[y] = located-coordinate crashes citywide in y / mean over Y_START..Y_END. Crashes counted within 250 m (haversine). Effect = DiD (post mean − pre mean)_treated − (…)_control, post=rel 1..3, pre=-3..-1, borough-reweighted to treated borough mix. Bootstrap resamples site_id within group, B=500 seed 42 (pipeline), B=200 in app callbacks. Preservation sites = quasi-placebo (no new structure): say so. Multi-building crash double counting is accepted at building level but inference is at site level; document.
 `event_building.parquet`: building_id,site_id,group('treated'|'control'),cohort(c),contaminated,comp_year,rel_year(-3..3),construction_type,borough,size_bin,total_units,crashes,adj,ped_cyc_crashes,injured (one row per building×rel_year, rel_year 0 included but excluded from stats). Replaces `event_study.parquet` (drop it). housing_clean keeps pre3_adj/post3_adj/event_eligible for display.
